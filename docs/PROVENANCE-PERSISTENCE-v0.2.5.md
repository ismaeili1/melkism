# MELKISM v0.2.5 — Provenance Persistence Foundation

## Stage 2 — Provenance Persistence Contract

This stage establishes the persistence boundary for provenance
records generated by the MELKISM ingestion runtime.

## Responsibilities

The contract supports:

- provenance creation
- lookup by provenance ID
- lookup by source
- lookup by provenance stage
- lookup of child records
- controlled updates
- deletion
- existence checks

## Provenance Chain

The persistence layer preserves:

Source
→ Fetch
→ Normalization
→ Validation
→ Ingestion

through the existing `parentId` relationship.

Persistence therefore stores the provenance chain without taking
responsibility for constructing or interpreting the ingestion
pipeline itself.

## Architectural Boundary

This contract does not implement:

- Prisma
- PostgreSQL
- database connections
- HTTP
- filesystem storage
- external services
- caching

## Dependency Direction

The dependency direction is:

Provenance Types
→ Provenance Persistence Contract
→ Persistence Implementation

The Runtime remains independent:

Provenance Runtime
→ Provenance Contract

and later:

Provenance Persistence Adapter
→ Provenance Persistence Contract

## Design Principle

The ingestion runtime must not depend directly on a persistence
technology.

A future Prisma repository or another persistence mechanism must
implement this contract rather than changing the ingestion runtime.
